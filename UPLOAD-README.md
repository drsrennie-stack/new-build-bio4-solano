# What to upload, and in what order

387 files. Everything in this zip is newer than what is on GitHub right now,
and nothing in it is older, so uploading all of it cannot undo anything you
have done. I checked that file by file before building it.

## Before anything else

Your uploads from today are already merged in. Your day-one slide deck
(`slides-course-introduction.html`), the "How this course works" entry on the
welcome page, the same entry on tools and links, and your reworded flashcards
blurb are all in here as you wrote them. Where we had both edited the same
line, it was the iframe height sender every time, and this zip carries the
version that measures the page instead of the frame.

## How to upload

GitHub's web uploader takes up to 100 files per drop, so this is four passes.

1. Unzip the file into a folder.
2. In the repo, click **Add file, Upload files**.
3. Select about 100 of the loose files, drag them in, commit.
4. Repeat until the loose files are gone.
5. Drag the `_retired` folder in on its own last, as a folder, so the file
   inside it keeps its path.

Order does not matter. GitHub Pages rebuilds after each commit and the site
stays usable throughout, because every page in here works with both the old
and the new versions of the others.

## After the upload

Two things are not files and will not fix themselves.

1. **Kajabi.** Re-paste the embed code from `kajabi-embed-kit.html` on the
   pages you embed. Without it the frame cannot shrink back down and the
   Course tools button will not follow the screen.
2. **Nothing else.** Canvas links point at page names that have not changed.

## If something looks wrong tomorrow

Check the live page, not a copy in your Downloads folder. That caused a scare
once already this week.
